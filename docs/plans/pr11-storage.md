# Storage and migrations

## Observable

Explicit migrations create two isolated PostgreSQL schemas; independent
connections see committed writes; scoped recall returns k eligible results and
has p95 below 300 ms on 10,000 frames. Existing unversioned databases are rejected.

## Owned files

- `gluomem/storage/**`: replace PostgreSQL SQL with dimensioned Core metadata,
  reject unmigrated schemas, autocommit transactions, iterative HNSW, qmark
  parsing, shared LIKE search, SQLite version gate, remove dead aliases.
- `gluomem/migrations/**`: metadata-aware Alembic, packaged template, revision
  command, fresh autogenerated 0001 with frozen DDL.
- `gluomem/cli.py`: migrate section only.
- `gluomem/extras.py`, `gluomem/timeutil.py`: optional imports and clock helper.
- `tests/storage/**`, `tests/migrations/**`, `tests/postgres/**`: contracts.
- `pyproject.toml`: postgres pytest marker only.
- `.github/workflows/ci.yml`, `Makefile`, `scripts/wheel_smoke.py`: live PostgreSQL
  CI, wheel Python matrix and core-only import boundary.

## Delete first

Delete legacy SQLite upgrade test and upgrader, both mocked PostgreSQL SQL-string
tests, fake SQLite recall latency test, PostgreSQL SQL source and old revision.
Replace the legacy upgrade test with a parametrized schema rejection contract;
replace mocked search assertions with live scope-isolation coverage.

## Decisions

Schema identifiers are lowercase SQL identifiers. PostgreSQL metadata has no
schema; migrations use a transaction-local search_path including public, with
version table in the chosen schema. The vector extension lives in public.
Backend connections are thread-confined. SQLite version 1 has no legacy upgrade.
Schema/dependency/CI changes were authorized by the supplied assignment.
Projection row IDs do not autoincrement; their IDs come from parent rows. Empty
vector batches remain no-ops. Wheel-check temporary directories live under
`/tmp` so cleanup is explicitly confined to disposable state.

## Regeneration

With an empty schema and the old revision removed:

`uv run gluomem migrate revision --autogenerate -m "initial scoped schema" --dsn postgresql://postgres:pg@127.0.0.1:55501/postgres --schema w1_generate --vector-dim 384`

Generated 0001 must retain frozen DDL, with vector dimension explicitly
substituted from migration configuration and extension installation prepended.
The integrator must port the other branches' bridge/suppression/job changes
into metadata and regenerate before merging.
Review generated imports, remove the autogenerated narration comments, split
long constraint/Computed literals, then run `uv run ruff format
gluomem/storage gluomem/migrations` and `uv run ruff check
gluomem/storage gluomem/migrations --fix`.
